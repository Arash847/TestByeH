Fix make implicit-rule collision on the dump860 target

Target `dump860` was matching make's builtin "%: %.c" rule against
dump860.c, so after the real build succeeded make ran a second, bogus
compile that tried to link the source with the already-built ELF:

  prospero-clang ... dump860.c byepervisor_dump_0860.elf -o dump860
  ld.lld: error: undefined symbol: notifyf

That "undefined symbol" came from make building the wrong target, not
from the payload. Declaring the targets phony stops the implicit rule
from applying.
