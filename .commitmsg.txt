Fix root cause of the missing gdb stub; two dumper bugs found by reading the stub

Root cause: the prosper0gdb stub is compiled out by default. In
ps5-kstuff/main.c:

    #ifndef DEBUG
    #define dbg_enter()
    #define gdb_remote_syscall(...)
    #endif

So the kstuff.elf built earlier had dbg_enter() as a no-op and never bound
a port. Scanning 1234-1300 against the console confirmed it: 9021 was open
(elfldr healthy) but no stub port anywhere. The build now exports
EXTRA_CFLAGS=-DDEBUG, which make reads from the environment and threads
into both the payload.elf and uelf compile rules.

Two dumper bugs found by reading gdb_stub/dbg.c, both of which would have
failed against the real stub:

 - real_dbg_enter() requires the client's FIRST byte to be a literal plus
   sign and returns immediately otherwise, killing the stub outright. The
   dumper sent its qSupported packet first. mock-r0gdb.ps1 now models this
   requirement so the test covers it rather than the console discovering it.
 - Write-Host with an unparenthesised format string followed by -f is
   parsed as Write-Host taking -f as a parameter, which binds the second
   operand to -ForegroundColor and fails on a numeric value.

Re-verified against the mock: plus handshake accepted, 8192 bytes, zero
mismatches, no errors.
