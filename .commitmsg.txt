Census the next level under each populated PML4 slot

The walk trace pinned it: PML4E[511] is a valid PDPT, but PDPTE[510]
reads back as zero. The read succeeded (rc=0); the entry is genuinely
empty. Since KERNEL_ADDRESS_TEXT_BASE resolves to PML4 index 511 and PDPT
index 510, 0xFFFFFFFF81000000 is NOT mapped on this firmware.

That means the SDK's text base does not hold here, and every dump range
derived from it was pointed at nothing. It also means the earlier
"K = 0xC70000 confirmed" result was weaker than stated: that figure came
from DATA_BASE - TEXT_BASE of the same table, so it agreed with itself
rather than being independently validated. The decisive test is whether
TEXT_BASE actually maps, and it does not.

This reads the next level under each populated slot and reports the live
sub-indices and the virtual addresses they map, so the real kernel
mapping can be read off the console instead of guessed at. Four 4KB
reads, all in one run.
