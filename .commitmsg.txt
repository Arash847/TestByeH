Trace every level of the page walk instead of reporting pass/fail

Physmap reads are not XOM blocked: the whole 4KB PML4 came back with
rc=0, and the decoded table is coherent.

    [  0] -> 0x243f3000  PW
    [282] -> 0x230a0000  PW  PS (1GB page)
    [367] -> 0x24208000  PW   <- this is pm_cr3, the recursive map
    [511] -> 0x230b5000  PW   <- kernelmap, which kernel text lives behind

Entry 511 is present and points onward, so the walk should proceed. The
dumper reported only "walk failed", with no indication of which level,
which is why several rounds went into guessing. This logs the table base,
index, read address, entry and flags for every level, and stops at the
first failure with the reason.

It also attempts a 16-byte text read once the leaf is reached, so a
successful walk is immediately confirmed by the bytes.
