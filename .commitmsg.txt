Add a kernel-text locator built on the census result

The level census established the real kernel mapping. PML4E[511] is the
kernelmap slot and its live PDPT indices are 0,1,2,3 and 511. Restoring
the canonical high half that the census printout dropped:

    slot 511 sub   0 -> 0xFFFFFF8000000000   <- kernelmap base
    slot 511 sub   1 -> 0xFFFFFF8040000000
    slot 511 sub   2 -> 0xFFFFFF8080000000
    slot 511 sub   3 -> 0xFFFFFF80C0000000
    slot 511 sub 511 -> recursive window

KERNEL_ADDRESS_TEXT_BASE, 0xFFFFFFFF81000000, resolves to PML4 index 511
and PDPT index 510 -- and PDPTE[510] is zero. The SDK base is not mapped on
this firmware, which is why every dump range so far pointed at nothing.

That also settles what the physmap is for: XOM guards the virtual mapping
of .text, but a whole 4KB PML4 came back through dmap with rc=0, so
physical access is not blocked. Walking to a physical address and reading
via the physmap is the way in.

This walks from the real kernelmap base, stepping forward in 2MB if the
first address is a hole, and reads 64 bytes at the first mapped physical
address. Those bytes are the answer to whether kernel text can be dumped
on 8.60 at all.
